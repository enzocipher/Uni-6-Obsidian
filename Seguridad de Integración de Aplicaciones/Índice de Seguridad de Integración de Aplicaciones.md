## Ruta de estudio y proyecto

| Paso | Resultado |
|---|---|
| Entender | Proceso, inventario y ecosistema de aplicaciones |
| Representar | Arquitectura AS-IS y supuestos justificados |
| Analizar | Activos, exposición, dependencias y matriz inicial de riesgos |
| Rediseñar | TO-BE con trazabilidad riesgo, principio y decisión |
| Controlar acceso | Catálogo de APIs y modelo AuthN/AuthZ con diagrama y reglas |
| Proteger datos | Matriz de datos, sensibilidad, riesgo, necesidad y control |

Estudiar en ese orden y utilizar el mismo proceso de negocio para conectar los entregables. Los diagramas y matrices deben describir los mismos componentes, consumidores, datos y riesgos.
